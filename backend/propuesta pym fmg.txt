| Historial de Estado | Registro de los cambios de estado de una solicitud (ej: “en revisión”, “aprobada”, “rechazada”). |


id	Identificador único del registro de estado.
solicitud_credito_id	Clave foráneaque enlaza con la entidadSolicitud de Crédito.
estado_anterior	Estado previo de la solicitud (ej:"borrador","enviada"). Puede ser nulo si es el primer estado.
estado_nuevo	Nuevo estado de la solicitud (ej:"en revisión","aprobada","rechazada","desembolsada").
fecha_cambio	Fecha y hora exacta en que se produjo el cambio de estado.
usuario_responsable_id	Clave foráneaal usuario que realizó el cambio (es el operador es automático).
tipo_usuario_responsable	Indica quién realizó la acción (útil si no quieres depender solo de FKs).
comentario	Nota adicional (ej: "Falta comprobante de domicilio", "Aprobado por política de riesgo").
ip_origen	Dirección IP desde donde se realizó el cambio (útil para auditoría de seguridad).
motivo_rechazo	Si el estado es"rechazada", se registra el motivo específico.
dias_en_estado_anterior	Cuántos días estuvo la solicitud en el estado anterior (útil para métricas

📝 HISTORIAS DE USUARIO
ÉPICA 1: Registro y Autenticación
HU-001 Como PYME, quiero registrarme en la plataforma para poder solicitar créditos de manera digital.
•	Criterios de aceptación:
•	Formulario con validación de RUC
•	Verificación por email
•	Creación de contraseña segura
HU-002 Como PYME, quiero iniciar sesión de forma segura para acceder a mi panel de solicitudes.
•	Criterios de aceptación:
•	Autenticación con email/contraseña
•	Opción de recuperar contraseña
•	Sesión con timeout de seguridad
ÉPICA 2: Solicitud de Crédito
HU-003 Como PYME, quiero completar un formulario de solicitud de crédito para iniciar el proceso de evaluación.
•	Criterios de aceptación:
•	Formulario paso a paso (wizard)
•	Guardado automático de avances
•	Validaciones en tiempo real
HU-004 Como PYME, quiero cargar los documentos requeridos para completar mi solicitud.
•	Criterios de aceptación:
•	Drag & drop para archivos
•	Formatos permitidos: PDF, JPG, PNG
•	Tamaño máximo 10MB por archivo
•	Vista previa de documentos
HU-005 Como PYME, quiero firmar digitalmente los documentos para validar legalmente mi solicitud.
•	Criterios de aceptación:
•	Integración con servicio de firma digital
•	Certificado con timestamp
•	Descarga de documentos firmados
HU-006 Como PYME, quiero ver el estado de mi solicitud en tiempo real para estar informado del proceso.
•	Criterios de aceptación:
•	Dashboard con timeline del proceso
•	Notificaciones de cambios de estado
•	Indicador de documentos pendientes
ÉPICA 3: Gestión de Operadores
HU-007 Como Operador, quiero ver un listado de solicitudes pendientes para gestionar mi trabajo diariamente.
•	Criterios de aceptación:
•	Filtros por estado, fecha, monto
•	Ordenamiento por prioridad
•	Paginación de resultados
HU-008 Como Operador, quiero revisar y validar documentos para aprobar o rechazar solicitudes.
•	Criterios de aceptación:
•	Visor de documentos integrado
•	Checklist de validación
•	Campo de observaciones
HU-009 Como Operador, quiero actualizar el estado de las solicitudes para mantener el flujo de trabajo.
•	Criterios de aceptación:
•	Cambio de estado con justificación
•	Registro de auditoría
•	Notificación automática al cliente
HU-010 Como Operador, quiero asignar tareas a otros operadores para distribuir la carga de trabajo.
•	Criterios de aceptación:
•	Selección de operador disponible
•	Definición de prioridad
•	Fecha límite de tarea
ÉPICA 4: Comunicación y Soporte
HU-011 Como PYME, quiero recibir notificaciones sobre mi solicitud para estar informado de cualquier cambio.
•	Criterios de aceptación:
•	Notificaciones por email
•	Notificaciones en la plataforma
•	Configuración de preferencias
HU-012 Como PYME, quiero acceder a un chat de soporte para resolver dudas durante el proceso.
•	Criterios de aceptación:
•	Chat en tiempo real
•	Historial de conversaciones
•	Indicador de operador en línea
ÉPICA 5: Evaluación y Análisis
HU-013 Como Operador, quiero ver el resultado de la pre-evaluación de riesgo para tomar decisiones informadas.
•	Criterios de aceptación:
•	Score crediticio visible
•	Factores de riesgo detallados
•	Recomendación del sistema
HU-014 Como Administrador, quiero generar reportes de solicitudes para analizar el desempeño del proceso.
•	Criterios de aceptación:
•	Filtros por periodo
•	Exportación a Excel/PDF
•	Métricas clave (aprobación, tiempos)
ÉPICA 6: Integraciones (Nice-to-have)
HU-015 Como PYME, quiero conectar mi sistema contable para agilizar la carga de información financiera.
•	Criterios de aceptación:
•	Integración con APIs contables
•	Mapeo automático de datos
•	Sincronización periódica
HU-016 Como Operador, quiero que el sistema valide automáticamente la identidad del solicitante para reducir fraudes.
•	Criterios de aceptación:
•	Integración con servicios KYC/AML
•	Validación de documentos de identidad
•	Alertas de riesgo
Tecnologías
Generales: Nodejs(gestion mediante npm), express, postgresql, TypeScript, 
Detalalladas: 
Despliegue: Render usando Contenerización con Docker 
TypeORM: Un Object-Relational Mapper (ORM) para interactuar con la base de datos 
 dotenv: Utilizado para la gestión de variables de entorno 
 Postman/  Supertest + Jest/Mocha o Python + pytest + requests, 
 Operaciones CRUD:  sobre entidades cuando aplique
seguridad:manejo de contraseñas cifradas (encrypted password handling y JWT /bearer tooken
Validación de Datos: data validation (rutinas de validación campos y otros)
 Borrado Lógico (Soft Delete): ??? usaremos
Manejo de Errores (Handling Errors): mensajes de error personalizados y relevantes tanto para solicitudes exitosas como para situaciones de error, como campos faltantes o datos inválidos, garantizando una experiencia de usuario fluida y una fácil identificación de problemas.
